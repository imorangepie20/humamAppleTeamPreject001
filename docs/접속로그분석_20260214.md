## 8. IP 분석 한계

| 항목 | 값 |
|------|-----|
| Nginx `$remote_addr` | `172.217.161.42` (전체 요청 동일) |
| `$http_x_forwarded_for` | `-` (전부 없음) |
| IP 대역 | Google 인프라 (172.217.x.x) |

**원인**: TP-Link DDNS(`imapplepie20.tplinkdns.com`) 터널이 Google Cloud 프록시를 경유하면서 실제 클라이언트 IP를 전달하지 않고 자체 프록시 IP로 대체함.

**영향**:
- 본인 접속과 스캐너/봇이 동일한 IP로 기록되어 **IP 기반 구분 불가**
- fail2ban 등 IP 차단 시 본인도 함께 차단됨 → **IP 차단 사용 불가**
- 현재는 **Referer/User-Agent 기반 분류가 유일한 구분법**
  - 본인 접속: `Referer`에 `imapplepie20.tplinkdns.com` 포함
  - 스캐너/봇: `Referer`가 `-`이거나 수상한 UA
